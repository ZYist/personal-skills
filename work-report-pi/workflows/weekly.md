# 生成周报流程

## 输入
- 可选 `--start YYYY-MM-DD --end YYYY-MM-DD`(默认:本周一到今天)
- 范围 = 用户说的"本周/上周/这周"或显式日期段

## 步骤

### Step 1: 确定范围
- 默认本周:周一(含)到今天
- 用户说"上周":上周一到上周日
- 用户给显式日期:直接使用

### Step 2: 拉本机活动(范围)
```bash
node scripts/parse-pi-sessions.cjs --start YYYY-MM-DD --end YYYY-MM-DD
```
- 输出含 `days` 按天聚合(每天 user/tool/errors 数),`events` 带 `day` 字段
- 按天读取 user 消息和 tool 调用,重建每天的"做了什么"

### Step 3: 拉钉钉活动(范围)
```bash
node scripts/fetch-dingtalk.cjs --start YYYY-MM-DD --end YYYY-MM-DD
```
- `behavior` 已按日期过滤到范围内
- 注意:dws 时间词只支持"今天/过去一周"等模糊词,脚本已对返回按日期字段精确过滤

### Step 4: 按天合并
- 每天:本机 user 消息 + 钉钉 behavior + 日历日程 → 当天工作条目
- 跨天重复任务(如某 bug 连续几天跟进)→ 合并成一条,标注时间跨度

### Step 5: 生成周报
- 按 `docs/weekly-template.md` 组织,对应钉钉"周报"模板字段:
  - **本周完成工作**:按天汇总的成果条目
  - **本周工作总结**:跨天趋势/共性问题/方法论(如"定位了 X 类问题的共性根因")
  - **下周工作计划**:从待办和进行中任务推导(未完成的任务 + 明确的下步计划)
  - **需协调与帮助**:需要他人配合/权限/资源的事项
- 无数据的一天不编造;整个范围无数据 → 告知用户

### Step 6: 预览
🔴 **CHECKPOINT**:展示周报给用户确认,不直接结束。
- 用户说"改" → 回到 Step 4/5 调整
- 用户满意 → 完成(本 skill 只输出终端,不提交钉钉)

## 失败分支(if-then 三段式)

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 范围跨周末/节假日,部分天无数据 | 正常现象,只汇总有数据的天 | 在周报里注明"X 日无活动记录" |
| `behavior` 时间词返回噪音(旧记录) | 确认脚本已按日期字段过滤 | AI 生成时人工剔除范围外条目 |
| 用户要"上周"但说不清起止 | 按自然周计算(周一到周日) | 向用户说明所用范围并确认 |
| `truncated: true` | 用更大 `--limit` 重跑 | 以 `counts`/`days` 聚合为准,标注不完整 |
